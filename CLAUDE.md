# Immersive Apotheosis - Forge 1.20.1 Mod

## Orientation
Registration inventory and package layout live in `MODMAP.md` (generated by
`.mcmod-tools/modmap.py`). Read that instead of crawling `src/`. Design: `docs/Immersive_Apotheosis_Design_Spec.md`.

## Quick Reference
- **Mod ID**: `immersive_apotheosis`
- **Package**: `com.otectus.immersiveapotheosis`
- **MC / Loader / Java**: see `gradle.properties` (Forge, Java 17)
- **Mappings**: official
- **Network protocol**: `ModNetwork.VERSION` = `"2." + WorkDefinition.VERSION`; bump `WorkDefinition.VERSION` whenever
  simulation behaviour changes, because client and server must run identical simulations.

Version numbers live only in `gradle.properties`; `processResources` expands them into `mods.toml`.

## Build
- `.mcmod-tools/gradlew-quiet.sh <dir> compileJava` for iteration; `build` also runs the JUnit suite (`src/test`).
- `runGameTestServer`, plus `-PapothicCurios` and `-PnoSmithing -PnoTanning -PnoJewelry -PnoEnchanting -PnoCurios`
  (standalone). Run all three after touching bridges, categories or stations.
- `runClient -PsmokeTest`: the client agent (`src/smokeTest`) plays all four stations and writes
  `run/smoketest/smoketest-result.json`.
- `build smokeTestJar`, then `python3 tools/packtest/ultima_pack_test.py --label <name>`: an isolated copy of the
  Ultima instance, evidence in `build/packtest/<label>/`. The real instance is never modified.
- `python3 tools/sync_libs.py [--check]` copies the sister mods' built jars into `libs/` (run before tests).
- `python3 tools/generate_jewelry_affixes.py [--check]` regenerates the jewelry affix data and lang.

## Structure
```
bridge/     socket floors, craft grades; bridge/<sister>/ loaded only by BridgeBootstrap (class name after ModList check)
category/   jewelry LootCategories, rules, gem bonuses, worn affixes, ApothicCurios exclusion status
minigame/   pure deterministic station simulations: no Minecraft imports, StrictMath for transcendentals
session/    server-authoritative sessions, input admission, bypass permissions
station/    one class per Apotheosis station: capture, revalidate, resolve/abandon against the real menu
network/    SimpleChannel packets (inputs only; never scores or items from the client)
mixin/      hooks into Apotheosis menus, vanilla menus and ApothicCurios
client/     overlay, input capture, tooltips, key mappings (client-only; common code must not import it)
```

## Key Dependencies
- Apotheosis, Placebo, Apothic Attributes: required (`implementation`, Modrinth ids in `gradle.properties`).
- Immersive Smithing, Tanning, Jewelry, Enchanting: optional; `compileOnly` from `libs/`, imported only inside
  `bridge/<sister>/`.
- Curios (API compileOnly) and ApothicCurios (`libs/`, runtime only with `-PapothicCurios`): optional.

## Conventions
- Server config only (`config/ServerConfig.java`, `ModConfig.Type.SERVER`); gameplay events on the FORGE bus via
  `@Mod.EventBusSubscriber`; the MOD bus has only `commonSetup` and `client/KeyRegistration`. No DeferredRegisters.
- Mixins into Apotheosis use `remap = false` and list both names (`{"clickMenuButton", "m_6366_"}`); vanilla
  targets use the refmap. The ApothicCuriosMixin is `require = 0`; `MixinPlugin` records whether it applied.
- Stations charge abandonment at the head of each menu's `removed()`; the session is removed before items change.
- Apotheosis always decides what is rolled; performances only choose within Apotheosis's own bounds.
- Sister repos (Smithing, Tanning) may carry uncommitted user work: never overwrite it.
